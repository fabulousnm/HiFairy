# Fairy 语音推理部署比较

2026-11-19。目标：尽量缩短从回答文字就绪到手机首次出声的时间，并尽量接近参考仓库的 Fairy 音色。用户反馈 ZipVoice 离线测试包在 nova 14 卓易通内推理时闪退。

## 已确认与未确认

- 测试包包含 arm64 sherpa-onnx JNI、约 125MB ZipVoice 解码器、约 54MB 声码器、约 5.6MB 编码器及参考音频；APK 约 179MB。相同资源在本机 Windows CPU 上能生成有效 24kHz 音频，短句完整推理约 1.9 秒。这只排除了资源整体损坏，不能证明 Android 兼容环境可运行。
- 电脑为 Ryzen 7 8745H（8 核 16 线程）、RTX 4060 Laptop（8GB 显存）、约 16GB 物理内存。GPU 测量时可用显存约 6.8GB，取决于当前占用。
- **闪退原因未知。**当前 ADB 未检测到手机，没有 logcat、native tombstone 或 `ApplicationExitInfo`。需分辨：模型加载时死亡、按生成后 native 崩溃、内存压力被系统杀死，或音频播放层异常。不能仅凭“闪退”断定 OOM。Android 官方建议通过退出原因与 native crash 记录区分这些情况。
- 华为 nova 14 官方规格页未给出可用于推算此模型峰值内存及 Android 兼容层进程上限的数值；模型文件大小也不等于推理峰值 RAM。

## 路线比较

| 路线 | 速度潜力 | Fairy 音色还原 | 实施难度 | 当前结论 |
| --- | --- | --- | --- | --- |
| 手机 CPU 上的 ZipVoice + Fairy 参考音频 | 受手机 CPU、内存及卓易通约束；当前无真机延迟数据 | 零样本模仿，不能保证与参考仓库一致 | 中高：需定位闪退、控制内存、验证长文本与发热 | 目前无法作为可用方案；值得留作独立对照，不应接入正式应用 |
| 手机运行原版 Fairy GPT-SoVITS | 不确定；需移植 PyTorch/前端或导出 ONNX、适配 Android，再测延迟 | 使用同名角色权重，音色目标更直接 | 很高：运行时、中文文本前端、模型格式、内存及兼容环境均需处理 | 不适合当前阶段优先投入 |
| 电脑 GPU 常驻 GPT-SoVITS + 手机局域网播放 | 电脑有 8GB 显存；模型常驻可去掉每次加载开销。最终首声延迟仍需实测 | 可直接测试公开的 `Fairy-e10.ckpt` 与 `Fairy_e10_s870.pth`，更贴近参考实现 | 中：安装/校验模型与依赖、配置服务、局域网连接、手机流式播放 | **优先验证**，兼顾速度潜力与角色音色；电脑需开机且手机能访问服务 |

公开 Fairy 权重目录合计约 241MB，包含 GPT 与 SoVITS 权重及参考 WAV；运行时还需中文前端和基础模型，不能把 241MB 当作完整部署大小。官方 GPT-SoVITS 支持 Windows/CUDA 和 API v2 音频流。其文档中的 4060 Ti 的 RTF 数据是 **v2 ProPlus 的另一配置**，不能直接当作本机 RTX 4060 Laptop 或这套 Fairy 权重的速度。

## 推荐实现和验收顺序

1. 在电脑上先固定可运行的 GPT-SoVITS 版本、Fairy 权重与参考音频，使用本机命令行生成两段固定中文文本；记录冷启动、热启动、首段 PCM、整句推理、显存峰值和音色。先试听是否优于 ZipVoice，再接手机。
2. 模型保持常驻。手机通过局域网向电脑发送少量文字；电脑返回流式 PCM/WAV，手机收到第一段即可播放。长回答按句切分，预取下一句，并支持停止播报。总首声延迟应拆成手机请求、服务排队/文本前端、首段合成、网络传输和播放器缓冲五段测量。
3. 在相同网络上至少测短句与长句各三次，统计首声延迟和 RTF，同时盲听角色相似度、发音与漏字。只有达到实际目标再并入正式 APK。
4. 如需追查手机闪退，先取得崩溃阶段与日志。Android 12+ 可读取 `ApplicationExitInfo` 的退出原因和 native trace；有 ADB 时抓取 logcat。再决定是否做更小模型或修复 Android 包，而不是在未知原因上继续加大模型。

网络条件：电脑当前 WLAN IPv4 为 `10.180.31.212`，这是会变化的局域网地址。手机与电脑需能互访；同连 Wi-Fi 不一定保证客户端互通，必要时使用电脑热点或明确的家庭路由器。文字请求很小，音频流量也远低于常见 Wi-Fi 带宽，主要延迟仍取决于生成首段及播放器缓冲；局域网额外耗时需实测。服务只监听可信局域网接口并设置访问凭据。
