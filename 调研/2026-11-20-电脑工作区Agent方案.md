# HiFairy 手机对话、电脑工作区 Agent 方案

调研日期：2026-11-20。目标是在 nova 14 的现有 APK 中对话，让电脑上的 Agent 读取、编辑指定工作区并运行工具；手机与电脑可处于不同网络。

## 结论

推荐 **电脑运行官方 DeepSeek Harness（DSH），HiFairy 增加 Agent 模式，电脑增加一个受限桥接服务**。手机保留当前 Fairy 聊天界面、语音输入与播报；Agent 模式的消息由桥接服务交给电脑本地 DSH Host 的同一会话执行。工作区由电脑端选择并允许，手机不传任意磁盘路径。模型调用仍走 DeepSeek API，代码执行和文件读写在电脑上；电脑需在线、保持唤醒。此方案属于设计建议，尚未接入或验证。

## 用户确定的 Agent 交互方向（2026-11-20）

- 新对话中央眼徽长按约 5 秒进入 Agent 模式；Agent 模式长按眼徽约 5 秒返回 Chat 模式。切换动画暂定为眼徽中心向外扩散主题，眼徽本体同步变换。单击余额卡、快速双击眨眼继续保留；长按识别不能误触它们。模式是应用的顶层状态，两种模式的会话列表分开，切换后恢复各自当前会话。
- Agent 与现有电脑 Fairy 语音服务共用**一个对外网址**，在网关中按路径分流（例如 `/voice/stream` 与 `/agent/...`）；只共享入口和 TLS，不共用会话权限或访问令牌。现有语音客户端的 `/stream` 路径可由网关保留映射以兼容旧版本。
- Agent 会话需与电脑端 DSH **同一会话存储和事件源**，从手机创建的任务可在电脑 DSH 中继续，反向亦然。此前提议的独立 SDK `dsh_home` 不足以保证互通；优先对接正在运行的 DSH Web Host 的官方 Session Controller/Remote API，先做版本固定的双端会话互通 PoC，再决定是否写 Host 插件桥接。不能用独立运行时复制一份“看起来相同”的历史。
- 手机新建 Agent 会话优先选择电脑 DSH 中已注册且健康的 `fairy` Agent 预设；允许选择电脑端真实可用的其他预设，并显示名称及描述。参考仓库的 `cordis.patch.yml` 已含 `preset-fairy`，正常安装并重启 DSH 后可出现 Fairy 模式；手机端应从 Host 读取预设目录，不硬编码模式列表。若 Fairy 预设不存在或失效，明确提示并让用户选择，不静默换成另一模式。
- 工作区由电脑端设置默认/当前目标，手机新任务沿用电脑端配置；手机发送请求时仍要绑定明确的 workspace ID。DSH Web 的工作区是会话级选择，不能假定“电脑界面正显示的目录”就是所有新会话的全局默认。手机不提供任意路径输入；如电脑端有多个工作区，需在电脑端明确默认项。

## DSH 界面能力盘点与手机映射

| DSH 能力 | 手机 Agent 模式建议 |
| --- | --- |
| 新建、恢复、搜索、重命名、置顶、归档、分叉会话 | 第一阶段做新建/继续/重命名/归档与搜索；分叉、置顶在会话协议稳定后补齐。电脑端与手机端显示同一会话 ID。 |
| Agent 预设模式与默认模式 | 输入栏附近显示当前模式；新会话默认 Fairy，模式列表来自电脑 Host。已开始的会话按 DSH 规则锁定模式，不在中途强制改。 |
| 模型与思考强度 | 读取电脑 Host 当前会话配置并显示；切换时使用 DSH 会话接口，而非 APK 现有普通 Chat 设置。 |
| 权限预设 | 显示“仅可查看／工作区内修改／完全权限”；实验性的自动审查仅在 Host 提供且用户明确启用时显示。切换需要 Host 确认，完全权限要明显二次确认。 |
| 工具调用、命令、文件改动、子任务与计划 | 采用可折叠事件卡：状态、命令摘要、路径、输出、文件差异、子任务进度；不把工具日志混入 Fairy 正文气泡。 |
| 人工批准 | 弹出具体动作、目标和作用范围；允许/拒绝送回 Host。掉线时不能自动批准。 |
| 暂停/停止、排队输入、恢复与断线重连 | 保留 DSH 的事件序号和会话状态；中断应调用 Host 的取消接口，不能仅停止手机渲染。 |
| 附件、文件引用、工作区文件预览 | 先支持会话附件和文件引用；工作区文件浏览与差异预览按 Host 授权范围逐步加。 |
| 浏览器、终端、右侧面板等桌面工具 | 手机上先呈现结果与关键控制；完整桌面布局不直接照搬。 |

以上是根据官方组件文档的能力映射，具体 RPC 方法、认证和事件格式需在安装的 DSH 版本中验证。特别是“Agent 预设选择”和“权限预设选择”是两个独立控制，不应混为一项。

## 方案比较

| 方案 | 手机体验 | 电脑工作区 | 开发量与取舍 |
| --- | --- | --- | --- |
| 手机浏览器直接打开 DSH Web UI | 使用 DSH 原界面，不是 HiFairy 主题 | 原生支持 | 最快验证；异网需要安全入口、TLS、可信 Host 和登录令牌；移动布局需真机验证。 |
| **HiFairy + 电脑桥接 + DSH Host API** | 保留现有气泡、眼徽、语音与会话入口 | DSH 会话绑定电脑目录 | 推荐正式方案；需实现桥接协议、事件流、权限确认、断线恢复与 Host 会话映射。 |
| 在 APK 内自写 Agent 循环 + 电脑命令接口 | UI 可定制 | 需自行实现 | 重复造轮子，工具权限、上下文、会话恢复与审计的维护负担高。 |

官方 DSH 的 Web UI 需先选工作区，Agent 可以读取/编辑文件、执行命令，并按权限策略请求批准。官方 Python SDK 可用 `cwd` 绑定工作区、持久会话 ID、接收通知及恢复会话，可用于隔离 PoC；但用户要求与电脑 DSH 界面共享会话，正式方案应优先验证同一 Web Host 的 Session Controller/Remote API。DSH 仍属预览阶段，协议更新要锁定版本并做兼容测试。

## 推荐架构

`HiFairy Agent 模式（APK） ⇄ WSS/HTTPS 认证通道 ⇄ 电脑桥接服务（127.0.0.1） ⇄ 同一 DSH Web Host ⇄ 已授权工作区`

1. 电脑端配置工作区别名和绝对路径，例如“HiFairy 项目”→ `E:\HiFairy`；规范化路径并禁止从手机提交新根目录或 `..` 路径穿越。每个会话固定一个工作区，切换工作区须新建会话。
2. 手机 Agent 会话与现有 DeepSeek 普通聊天会话分开存储。消息流传递正文、思考、工具调用摘要、文件改动与运行状态；工具原始日志仅按需展开。
3. 写文件、运行高风险命令等操作沿用 DSH 的批准机制，手机显示具体命令、路径与影响后允许/拒绝；断线或无人回应时拒绝，绝不自动提升权限。
4. 中断先取消当前 Agent 运行；手机重连按会话 ID 取状态和缺失事件，不重复发送任务。电脑端持久化会话映射和事件序号。
5. 异网入口复用现有公网通道经验，但独立于语音服务的令牌与权限。正式使用优先私有组网或受控 HTTPS 反向代理；临时 Quick Tunnel 只用于测试。桥接仅绑定本机回环地址，手机密钥保存在系统安全存储，服务端令牌不可写入仓库。

## 分阶段实施

1. **电脑 PoC**：安装并固定 DSH 版本；安装/确认 Fairy 预设，验证同一 Host 上的会话列表、会话创建/恢复、模式目录、权限、工作区绑定、事件流与批准/拒绝。用一个测试工作区做文件读写。此阶段不改手机 App。
2. **局域网手机闭环**：桥接服务提供配对、工作区列表、会话创建、消息流、审批、取消与重连；APK 增加 Agent 模式和工具卡片。优先验证权限与断线语义。
3. **异网验证**：同一套协议经安全通道连接，测连接、首事件、任务完成、断线重连耗时；再整合现有语音输入与回答播报。
4. **稳定性**：版本锁定、事件落盘、工作区隔离、错误恢复、长任务通知与资源限制。

## 成本与限制

- DSH 在电脑上运行工具，并不意味着 DeepSeek 模型在电脑本地推理；仍需官方 API Key 与相应模型费用。
- 异网通道可先用免费测试方案，但公网入口长期稳定性、电脑在线和安全维护仍需解决。当前不承诺免费长期服务。
- 社区有非官方 DSH 手机远程项目，但其手机端使用 WebView/Relay，且项目明确声明未获 DeepSeek 审核；可作为交互参考，不直接接入其远程中继或 APK。
- 电脑当前环境未检测到 `dsh` 命令；正式实现先完成 PoC 安装和版本核验。
