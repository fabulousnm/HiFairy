# HiFairy 手机对话、电脑工作区 Agent 方案

调研日期：2026-11-20。目标是在 nova 14 的现有 APK 中对话，让电脑上的 Agent 读取、编辑指定工作区并运行工具；手机与电脑可处于不同网络。

## 结论

推荐 **电脑运行官方 DeepSeek Harness（DSH），HiFairy 增加 Agent 模式，电脑增加一个受限桥接服务**。手机保留当前 Fairy 聊天界面、语音输入与播报；Agent 模式的消息由桥接服务交给电脑本地 DSH 会话执行。工作区由电脑端选择并允许，手机只选择已授权工作区，不传任意磁盘路径。模型调用仍走 DeepSeek API，代码执行和文件读写在电脑上；电脑需在线、保持唤醒。此方案属于设计建议，尚未接入或验证。

## 方案比较

| 方案 | 手机体验 | 电脑工作区 | 开发量与取舍 |
| --- | --- | --- | --- |
| 手机浏览器直接打开 DSH Web UI | 使用 DSH 原界面，不是 HiFairy 主题 | 原生支持 | 最快验证；异网需要安全入口、TLS、可信 Host 和登录令牌；移动布局需真机验证。 |
| **HiFairy + 电脑桥接 + DSH SDK** | 保留现有气泡、眼徽、语音与会话入口 | DSH 会话绑定电脑目录 | 推荐正式方案；需实现桥接协议、事件流、权限确认、断线恢复与会话映射。 |
| 在 APK 内自写 Agent 循环 + 电脑命令接口 | UI 可定制 | 需自行实现 | 重复造轮子，工具权限、上下文、会话恢复与审计的维护负担高。 |

官方 DSH 的 Web UI 需先选工作区，Agent 可以读取/编辑文件、执行命令，并按权限策略请求批准。官方 Python SDK 可用 `cwd` 绑定工作区、持久会话 ID、接收通知及恢复会话，适合作为电脑桥接服务的运行接口。DSH 仍属预览阶段，协议与 SDK 更新要锁定版本并做兼容测试。

## 推荐架构

`HiFairy Agent 模式（APK） ⇄ WSS/HTTPS 认证通道 ⇄ 电脑桥接服务（127.0.0.1） ⇄ DSH SDK/运行时 ⇄ 已授权工作区`

1. 电脑端配置工作区别名和绝对路径，例如“HiFairy 项目”→ `E:\HiFairy`；规范化路径并禁止从手机提交新根目录或 `..` 路径穿越。每个会话固定一个工作区，切换工作区须新建会话。
2. 手机 Agent 会话与现有 DeepSeek 普通聊天会话分开存储。消息流传递正文、思考、工具调用摘要、文件改动与运行状态；工具原始日志仅按需展开。
3. 写文件、运行高风险命令等操作沿用 DSH 的批准机制，手机显示具体命令、路径与影响后允许/拒绝；断线或无人回应时拒绝，绝不自动提升权限。
4. 中断先取消当前 Agent 运行；手机重连按会话 ID 取状态和缺失事件，不重复发送任务。电脑端持久化会话映射和事件序号。
5. 异网入口复用现有公网通道经验，但独立于语音服务的令牌与权限。正式使用优先私有组网或受控 HTTPS 反向代理；临时 Quick Tunnel 只用于测试。桥接仅绑定本机回环地址，手机密钥保存在系统安全存储，服务端令牌不可写入仓库。

## 分阶段实施

1. **电脑 PoC**：安装并固定 DSH 版本；选测试工作区，验证读文件、改一个测试文件、命令输出、批准/拒绝、取消和恢复。此阶段不改手机 App。
2. **局域网手机闭环**：桥接服务提供配对、工作区列表、会话创建、消息流、审批、取消与重连；APK 增加 Agent 模式和工具卡片。优先验证权限与断线语义。
3. **异网验证**：同一套协议经安全通道连接，测连接、首事件、任务完成、断线重连耗时；再整合现有语音输入与回答播报。
4. **稳定性**：版本锁定、事件落盘、工作区隔离、错误恢复、长任务通知与资源限制。

## 成本与限制

- DSH 在电脑上运行工具，并不意味着 DeepSeek 模型在电脑本地推理；仍需官方 API Key 与相应模型费用。
- 异网通道可先用免费测试方案，但公网入口长期稳定性、电脑在线和安全维护仍需解决。当前不承诺免费长期服务。
- 社区有非官方 DSH 手机远程项目，但其手机端使用 WebView/Relay，且项目明确声明未获 DeepSeek 审核；可作为交互参考，不直接接入其远程中继或 APK。
- 电脑当前环境未检测到 `dsh` 命令；正式实现先完成 PoC 安装和版本核验。
