# 手机工作区与应用操作可行性

> 发布状态（v1.0.0）：卓易通拒绝授予 APK 无障碍权限，原 APK 手机应用操作服务、设置页及 DSH 工具已从首版撤回。以下应用操作部分保留为历史调研，不代表发布版具备该能力。未来若继续探索，先用独立原生 HAP 探针验证。

适用范围：HiFairy APK 运行于 nova 14 的卓易通兼容环境，Agent 推理仍在电脑 DSH。结论以 2026-11-27 的官方接口文档和当前仓库能力为准；卓易通与原生鸿蒙之间的实际跨界能力须真机验证。

## 当前能力与缺口

项目起点仅通过系统选择器读取附件、创建下载文件；Agent 右侧抽屉浏览和上传下载的是**电脑**文件。此后手机工作区手动挂载、受限文件工具与 DSH 端到端读写均已在兼容区目录真机通过。手机应用操作的设置、无障碍服务和 DSH 工具已实现，仍待 nova 14 验证卓易通能否开启服务并暴露目标应用节点。

## 1. 手动挂载手机工作区并限定文件操作

**Android 兼容区内有条件可行。** 使用系统 `ACTION_OPEN_DOCUMENT_TREE` 让用户在设置中选定目录，保存 URI 的持久读写授权；所有列目录、读、写、创建、移动操作只接受该树下的 `DocumentFile`/`DocumentsContract` URI，不接受 Agent 传来的绝对路径。当前只允许一个或少数明确挂载的工作区；每次执行前检查授权仍有效、目标确属该树，并对覆盖写入采用临时文件或备份与显式确认。电脑 DSH 需要新增受限的“手机文件工具”请求，由手机端执行并回传结果，电脑端不持有手机文件系统路径。

范围限制：Android 11 起不能用目录选择器授权内部存储根目录、`Download` 目录或 `Android/data`、`Android/obb`；其他应用的私有目录也不能随意读写。[Android SAF](https://developer.android.com/training/data-storage/shared/documents-files)、[Android 11 存储限制](https://developer.android.com/about/versions/11/privacy/storage)。华为说明，卓易通应用访问鸿蒙本机文件时，需要在选择器中找到 `MyHarmonyDevice` 映射入口；能否对该入口取得持久目录写授权，文档未明确，必须在 nova 14 验证。[华为卓易通文件说明](https://consumer.huawei.com/cn/support/content/zh-cn16048495/)。

真机验证（2026-11-27）：`我的设备（鸿蒙）/Test` 可经系统弹窗选定并取得持久目录授权，但 `DocumentsContract.createDocument` 报底层 `MyHarmonyOSDevice/Test/... Permission denied`；用户进一步验证该入口中的文件夹均不可修改，而其他兼容区文件夹可修改。**判定：当前 APK 的可写工作区仅支持实际通过读写测试的兼容区普通文件夹；不开放 `我的设备（鸿蒙）` 映射目录或系统敏感目录挂载。** 该错误发生在桥接映射后的底层创建步骤，目录授权不等于映射目录的完整写入能力。华为只说明卓易通应用可通过该映射入口*选择*鸿蒙本机文件，没有承诺目录树创建与覆盖能力。[华为卓易通文件说明](https://consumer.huawei.com/cn/support/content/zh-cn16048495/)。鸿蒙原生 FilePicker 的保存接口允许用户选位置、获取可写 URI，但这是原生应用接口，不能直接推出卓易通 APK 拥有同样的目录能力。[华为保存用户文件](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/save-user-file/)。

原因判断：鸿蒙的应用沙箱与 Picker 授权按 URI 和操作范围隔离，直接向公共目录绝对路径写入并非通用许可；兼容区还存在 `MyHarmonyOSDevice` 跨环境映射，实际文件提供者是否支持创建取决于映射实现。[华为文件管理 FAQ](https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/faqs-network-133/)、[Android SAF](https://developer.android.com/training/data-storage/shared/documents-files)。目前证据支持“该映射目录创建不被允许”，尚不能证明是某个具体系统权限级别，也不应建议申请更高权限来绕过。

## 2. 设置中选择允许操作的应用与权限

**兼容区内 Android 应用可先试；原生鸿蒙应用不作可用承诺。** 设置页逐个添加可见的应用及允许的动作，例如“打开”“读取界面”“点击/滑动”“输入文本”。Android 11 起应用列表受 package visibility 过滤，应只声明要交互的具体包或相关 Intent 查询，不默认申请全部应用可见权限。[Android 包可见性](https://developer.android.com/training/package-visibility/declaring)。

标准 Android 方案是优先调用目标应用公开的 Intent/deep link；确需 UI 操作时，由用户在系统中手动开启 HiFairy 的 `AccessibilityService`，服务按设置中的包名和动作白名单过滤每一次操作，使用节点动作或 `dispatchGesture`。Android 官方 API 支持读取已授权窗口、全局操作和手势，但需要服务元数据声明并由系统授予无障碍权限。[AccessibilityService API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[服务配置](https://developer.android.com/guide/topics/ui/accessibility/service)。屏幕截图若另需 `MediaProjection`，Android 14 起每次捕获会话均需用户同意。[MediaProjection](https://developer.android.com/media/grow/media-projection)。

应用内的“允许应用/动作”是 HiFairy 自己的第二道边界，不能代替系统权限，也不会让卓易通 APK 获得控制鸿蒙原生应用的能力。先做三个真机探针：能否列出一个卓易通 Android 应用及一个原生鸿蒙应用；能否开启本 APK 的无障碍服务；节点树能否识别并操作两类应用。若第三项对原生应用不可用，原生应用操作须等鸿蒙原生端或目标应用提供开放接口。Shizuku 依赖 Android ADB/系统 API，不能据此推断可跨越卓易通与原生鸿蒙边界；其官方项目也提示厂商改动可能影响运行。[Shizuku 项目](https://github.com/RikkaApps/Shizuku)、[配置限制](https://github.com/RikkaApps/websites/blob/master/shizuku/guide/setup.md)。

## 2026-11-27 实施状态与下一项验证

文件侧：用户完成六项批量探针和正式插件验收。正式重命名通过 Android `DocumentsContract.renameDocument` 在兼容区目录报 `IllegalStateException: Failed to rename to ...`，但用户手动通过新建目标文件和删除源文件成功达到同一结果。代码现改为**先复制、读回校验、最后删除源文件**；目前只支持不超过 12 KB 的文本文件，不尝试目录改名或覆盖同名目标。此修复待真机重测。

应用侧：已在设置中加入可见 Android 兼容应用列表与逐应用的“启动／读取界面／点击／填写输入框／返回”开关；无障碍服务必须由用户在系统设置中手动开启。执行时再次核对当前前台包名与动作白名单；点击只按可见文字精确匹配，不作坐标盲点。DSH 插件可通过自然语言选择相应工具，手机 Agent 当前会话或进行中任务的前台服务接收请求。下一轮真机需验证：卓易通是否允许启动该服务、是否能列出目标应用、前台节点是否可读、点击与输入动作是否被目标应用接受。即使这些对兼容区应用通过，也不能据此推断可操作鸿蒙原生应用。[Android 无障碍服务配置](https://developer.android.com/guide/topics/ui/accessibility/service)、[节点和动作 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[应用可见性](https://developer.android.com/training/package-visibility/declaring)。

用户真机反馈：开启 HiFairy 服务时，系统提示“应用不支持获得系统无障碍权限”。一位卓易通用户安装另一款 Android 读屏应用时报告了几乎相同的提示“为了您的隐私安全，应用暂不支持获取系统无障碍权限”，且未能启用。[卓易通内读屏应用实测](https://bbs.tatans.cn/topic/136058)。这与 Android 13+ 侧载 APK 常见的“受限设置”不同：后者官方仍提供应用详情页的“允许受限设置”入口；前者提示为应用**暂不支持获取系统无障碍权限**，更指向卓易通/鸿蒙兼容边界。[Android 受限设置说明](https://support.google.com/android/answer/12623953)。目前未找到卓易通官方公开的无障碍能力矩阵，故结论是**该 nova 14 当前环境中的 HiFairy APK 无法启用 Android AccessibilityService**，不能以第三方论坛推断所有卓易通版本永久如此。可在 HiFairy 应用详情页检查是否存在“允许受限设置”，但若无此入口或设置后仍是同一提示，停止该路线。无障碍依赖的读屏、点击、输入、返回工具不能在此设备上使用；纯 Intent 启动、目标应用开放 API、或未来鸿蒙原生协作模块需分别验证，不应声称已替代无障碍。

## 3. 被卓易通阻断后的实现路线

推荐先做**独立原生鸿蒙 HAP 能力探针**，不立即重写 HiFairy APK。华为 Accessibility Kit 的原生 `AccessibilityExtensionAbility` 提供辅助扩展服务；扩展上下文有获取窗口根节点、查询元素、执行 `click`/`setText` 等动作，以及手势注入接口，能力声明中包括 `retrieve` 和 `gesture`。[扩展上下文与节点 API](https://developer.huawei.com/consumer/cn/doc/harmonyOS-references/js-apis-inner-application-accessibilityextensioncontext/)、[能力与动作列表](https://developer.huawei.com/consumer/cn/doc/harmonyOS-references/js-apis-accessibility/)。这是与卓易通 APK 的 Android `AccessibilityService` 不同的原生路径。官方接口存在不等于 nova 14 上任意三方 HAP 都能获权，也不保证能读到卓易通或所有原生应用的节点；必须实测。当前 API 文档还标记部分旧接口已废弃，编码时须以本机 DevEco SDK 对应版本为准。

探针使用独立包名和测试界面：① DevEco 构建、签名、安装 HAP；② 查看其辅助功能扩展是否出现在系统设置中并能手动开启；③ 读取探针自身测试页面的节点；④ 再读取一个用户选择的原生应用及一个卓易通应用的节点；⑤ 只对测试页面执行一次点击、输入和返回。每步记录设备版本、SDK、错误码和节点数量。若安装或授权要求受限权限/ACL，再按[华为受限权限申请说明](https://developer.huawei.com/consumer/cn/doc/harmonyOS-guides/declare-permissions-in-acl/)核对，不预设必须或必然可以通过审批。

若原生探针通过，再做轻量原生伴随端：它在手机侧保存允许操作的应用及动作，接入现有公网 Agent 网关并使用独立凭据；电脑 DSH 发起明确的 `inspect`、`click`、`setText`、`back` 请求，伴随端检查当前前台应用、白名单和请求时效后执行，结果返回当前会话。跨卓易通与原生 HAP 的进程通信不能默认成立，因此以现有网关为桥接点。敏感动作仍需用户确认；后台连接和系统进程保活另作真机测试。现有 APK 聊天、文件工作区和 DSH 会话链路无需为此重写。

不依赖界面控制的应用操作可先用目标应用公开的 App Linking/接口实现，但只覆盖目标应用明确开放的动作，不能泛化为读取与点击任意界面。[华为应用启动与 App Linking](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/app-startup-overview-V5/)。`UiTest` 和 HDC 可作为开发时的对照测试，官方将其定位于 UI 自动化测试，并要求测试应用/设备连接环境；不适合作为用户远离电脑时常驻的产品方案。[华为 UiTest 指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/uitest-guidelines/)。

**决策门槛：** 原生 HAP 能安装、启用并实际读取/操作目标应用节点，才投入伴随端开发；若只能操作自身或系统拒绝授权，停止通用 UI 控制，改为逐应用公开接口。不要通过提高卓易通 APK 权限、ADB 常驻或屏幕截图代替已被系统拒绝的操作能力。
